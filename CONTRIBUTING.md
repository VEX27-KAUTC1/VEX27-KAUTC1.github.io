# Contributing

Authorized members use a GitHub branch and pull request for every documentation change.

1. Create an Issue or pick one from the organization Project board.
2. Use the appropriate file in `templates/`, create or edit a Markdown page under `src/content/docs/`, and link the Issue.
3. Keep facts traceable: dates, units, CAD version, test conditions, and source links. Mark unknowns as pending. Keep private competition strategy outside this public repository.
4. Preview locally with `pnpm dev` when possible; CI runs structure, build, and link checks. Use the pull request preview and the checklist.
5. Request a reviewer; address comments; a maintainer merges after approval. The GitHub Actions workflow publishes the merged `main` branch.

Edit an existing page using Starlight's **Edit this page** link after the verified organization repository is configured. GitHub's web editor can create a branch and pull request; programming tools are optional.
